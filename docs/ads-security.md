# امنیت NX Ads

پنل NX Ads (`apps/ads-admin`) قرار است کنار سرور نقطه، روی همان دامنه، میزبانی شود. این سند می‌گوید پنل خودش چه چیزهایی را می‌بندد، سرور میزبان باید چه کند، و چه چیزی هنوز باز است.

## آنچه پنل خودش می‌بندد

| خطر                            | جلوگیری                                                                                                                                                                                                                                                                          |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ورود هر کسی به پنل             | پیش از هر چیز ورود لازم است: کد پیامکی شماره‌ی یک **ادمین نقطه** (`/auth/code/*`) و بعد بررسی با `/admin/api/me`. شماره‌ای که ادمین نیست همان لحظه بیرون می‌رود و نشستش روی سرور بسته می‌شود (`src/data/auth.ts`).                                                               |
| دزدیده شدن توکن                | توکن دسترسی فقط در حافظه است. توکن تازه‌سازی در `sessionStorage` است، یعنی فقط همین تب و تا بسته شدنش. ۳۰ دقیقه بی‌کاری خروج است. «خروج» نشست را روی سرور هم تمام می‌کند (`/auth/logout`). درخواست‌ها بدون کوکی (`credentials: "omit"`) و فقط با سرآیند `Authorization` می‌روند. |
| XSS از راه لینک آگهی           | شِمای مشترک (`packages/ads/src/schema.ts`، `httpsUrl`) فقط `https://` با نام دامنه می‌پذیرد، برای لینک و برای عکس. `javascript:`، `data:` و `http:` رد می‌شوند، هم در پنل و هم در هر کلاینتی که بسته را با همین شِما می‌خواند (نیوتب).                                           |
| اجرای اسکریپت تزریق‌شده        | CSP سخت‌گیر در صفحه‌ی ساخته‌شده (`vite.config.ts`، `CSP`): اسکریپت و اتصال فقط از خود پنل؛ عکس فقط https؛ بدون `object`، `base` یا فرم به جای دیگر. پنل هیچ HTML خامی نمی‌سازد (بدون `dangerouslySetInnerHTML`).                                                                 |
| قاب گرفتن پنل (clickjacking)   | پنل داخل قاب اجرا نمی‌شود (`src/main.tsx`). سد اصلی سرآیند `frame-ancestors 'none'` سرور است.                                                                                                                                                                                    |
| فایل یا درخواست خیلی بزرگ      | درون‌ریزی بیش از ۵ مگابایت رد می‌شود. مسیر توسعه‌ی بسته هم بیش از ۵ مگابایت را رد می‌کند (`413`).                                                                                                                                                                                |
| باز بودن سرور توسعه روی شبکه   | سرورهای `dev` و `preview` فقط روی `localhost` گوش می‌دهند. مسیر `POST /v1/ads/bundle` فقط در `vite dev` هست و در ساخت نهایی وجود ندارد. عبور از ورود (`VITE_NX_ADS_NO_AUTH=1`) هم فقط در حالت توسعه کار می‌کند و از ساخت نهایی حذف می‌شود.                                       |
| حمله‌ی برنامه‌ریزی‌شده به ورود | کد تازه فقط بعد از یک دقیقه درخواست می‌شود و شماره قبل از فرستادن بررسی می‌شود. محدودیت واقعی تعداد تلاش با سرور است (پایین).                                                                                                                                                    |

## میزبانی کنار سرور نقطه

پنل یک پوشه‌ی ایستا است (`pnpm --filter @dotlife/ads-admin build` → `apps/ads-admin/dist`):

- **مسیر:** آن را زیر یک مسیر جدا روی همان دامنه بگذار، مثلاً `https://noghte.life/nx-ads/`.
- **API:** پنل در ساخت نهایی API را از همان دامنه می‌خواند (`/api`). اگر API جای دیگری است، هنگام ساخت `VITE_NOGHTE_API` را بده، مثلاً `VITE_NOGHTE_API=/api`.
- **بدون پروکسی و CORS:** پروکسی `/noghte` فقط برای توسعه است. روی سرور واقعی لازم نیست و نباید CORS باز شود.

سرآیندهایی که سرور باید برای مسیر پنل بفرستد:

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' https: data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()
Cross-Origin-Opener-Policy: same-origin
Cache-Control: no-store            (فقط برای index.html؛ فایل‌های assets هش‌دار را می‌شود کش کرد)
```

با Fastify سرور نقطه (`@fastify/static`) این‌ها در `setHeaders` همان مسیر گذاشته می‌شوند. با nginx هر کدام یک `add_header … always` در `location /nx-ads/` است.

## کارهای سرور نقطه (خارج از این مخزن)

- **محدودیت تلاش برای ورود** (`/auth/code/request` و `/verify`)، به ازای شماره و IP، تا کد شش‌رقمی حدس زده نشود.
- **فهرست ادمین‌ها** (`deps.admins`) فقط شماره‌های لازم را داشته باشد. پیشنهاد: نقش جدا برای NX Ads (مثلاً `ads`) تا ادمین تبلیغات به همه‌ی پنل نقطه دسترسی نداشته باشد.
- **ثبت تغییرها:** هر نوشتن در `/admin/api/promos` و بعداً در مسیرهای NX Ads با شماره‌ی ادمین و زمان ثبت شود (`updated_by` الان هست).
- **کلید خصوصی امضای بسته** (ed25519) فقط روی سرور، بیرون از مخزن و بیرون از دسترس پنل بماند. کلید عمومی داخل کلاینت‌ها جاسازی می‌شود.
- **کوکی:** اگر روزی ورود با کوکی شد، کوکی `HttpOnly`، `Secure` و `SameSite=Strict` باشد. آن‌وقت توکن تازه‌سازی دیگر در دسترس JavaScript نیست.

## آنچه هنوز باز است

- **داده‌ها:** آگهی‌ها و کمپین‌ها هنوز در `localStorage` مرورگر ادمین‌اند (`LocalAdsStore`)، نه روی سرور. دو ادمین دو نسخه‌ی جدا دارند و پاک شدن داده‌ی مرورگر آن‌ها را می‌برد. جای درستشان مسیرهای `/v1/admin/*` سرور است (`docs/ads-api.md`)، با همان ورود و ثبت تغییر.
- **توکن در `sessionStorage`:** هنوز برای JavaScript خواندنی است. CSP خطر XSS را کم می‌کند ولی صفر نمی‌کند؛ راه کامل کوکی `HttpOnly` سمت سرور است.
- **امضای بسته:** بسته هنوز امضا نمی‌شود و نیوتب در حالت توسعه بسته‌ی بدون امضا را می‌پذیرد. پیش از استفاده‌ی واقعی، کلاینت باید امضای ed25519 را بررسی کند.
- **تصاویر:** عکس آگهی از نشانی https آگهی‌دهنده خوانده می‌شود، پس سرور او بازدید پنل و کلاینت‌ها را می‌بیند. برای حریم خصوصی کاربران، عکس‌ها بهتر است روی سرور خودمان کپی شوند (مثل `/config/media` نقطه).
