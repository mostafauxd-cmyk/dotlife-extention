# @dotlife/event-data

مناسبت‌ها و تعطیلات — داده با منبع (provenance) + موتور کوچک برای پیدا کردن رخدادها در هر روز.

## بسته‌ها (`PackId`)

| بسته                | محتوا                                                                     | تعداد | تعطیل؟          |
| ------------------- | ------------------------------------------------------------------------- | ----- | --------------- |
| `official-holidays` | تعطیلات رسمی ایران — ۱۰ خورشیدی + ۱۷ قمری                                 | ۲۷    | ✅ فقط این بسته |
| `religious`         | مناسبت‌های مذهبی غیرتعطیل (ولادت‌ها، شهادت‌ها، شب‌های قدر، عرفه، …)       | ۲۳    | —               |
| `national`          | ملی، فرهنگی و ادبی (معلم، حافظ، فردوسی، دانشجو، روز مادر/پدر، روز قدس، …) | ۲۶    | —               |
| `persian-cultural`  | جشن‌های ایرانی و ایران باستان (چهارشنبه‌سوری، مهرگان، یلدا، سده، …)       | ۸     | —               |
| `international`     | روزهای جهانی (میلادی)                                                     | ۱۶    | —               |
| `astronomy`         | اعتدال‌ها و انقلاب‌ها                                                     | ۴     | —               |

همه‌ی داده همیشه در `ALL_EVENTS` هست؛ **نمایش** با `packs` در کوئری تعیین می‌شود، نه با حذف داده (PLAN §125).

## قواعد (`EventRule`)

- `fixed` — روز ثابت در یکی از سه تقویم. `clampToMonthEnd` برای تاریخ‌هایی مثل ۳۰ صفر که در ماه‌های ۲۹روزه روی آخرین روز ماه می‌افتند.
- `last-weekday-of-month` — مثلاً روز قدس = آخرین جمعه‌ی رمضان. با `offsetDays` می‌توان جابه‌جا کرد: چهارشنبه‌سوری = یک روز پیش از آخرین چهارشنبه‌ی اسفند.

## تقویم قمری رسمی

رخدادهای قمری با **تقویم قمری رسمی (رؤیتی)** محاسبه می‌شوند، نه قمری حسابیِ `calendar-core`:

- `src/data/hijri-month-starts.ts` — روز اول هر ماه قمری رسمی (۷۳ ماه، ۱۴۴۴/۶ تا ۱۴۵۱/۳) که از داده‌ی time.ir تولید شده.
- `officialHijri(jdn)` — در بازه‌ی جدول دقیقاً برابر time.ir؛ بیرون از آن به قمری حسابی برمی‌گردد. `isOfficialHijriKnown(jdn)` می‌گوید کدام حالت است.
- وقتی تقویم سال جدید منتشر شد، ماه‌های تازه به جدول اضافه می‌شود (بدون تغییر کد).

## API

```ts
import {
  occurrencesOn,
  occurrencesInSolarMonth,
  isOfficialHoliday,
  isDayOff,
} from "@dotlife/event-data";

occurrencesOn(jdn, { packs: ["official-holidays", "national"] }); // Occurrence[] → { event, jdn, date (خورشیدی) }
occurrencesInSolarMonth(1405, 7, { packs: ALL_PACKS });
isOfficialHoliday(jdn); // تعطیل رسمی (بدون جمعه)
isDayOff(jdn); // تعطیل رسمی یا جمعه
```

## تست‌ها

- اعتبارسنجی دیتاست: id یکتا و kebab-case، عنوان و منبع و تاریخ برداشت برای همه، `holiday` فقط در بسته‌ی رسمی، روزها در بازه‌ی ماه، ۳۰ قمری فقط با `clampToMonthEnd`
- `officialHijri` روی **هر روزِ** داده‌ی time.ir دقیقاً برابر است؛ ماه ۳۰روزه‌ای که در تقویم حسابی ۲۹روزه است (شعبان ۱۴۴۵) درست برمی‌گردد
- رخدادهای مرجع: نوروز ۱۴۰۵، عاشورای ۱۴۴۷، عید فطر ۱۴۴۶، روز قدس ۱۴۰۴، چهارشنبه‌سوری ۱۴۰۳ و ۱۴۰۴، شهادت امام رضا در صفرِ ۲۹روزه

## چیزهایی که هنوز نیست

- تعطیلات موردی (مثل تعطیلی‌های اعلامی دولت) — نیاز به سرویس به‌روزرسانی از سرور
- ماه‌گرفتگی/خورگرفتگی در بسته‌ی نجومی
- جشن‌های باستانی با شمارش سی‌روزه (نسخه‌ی اول همان تاریخ‌های رایج امروزی را دارد)

## داخل اپ و دانلودی (PLAN قدم ۱۶‌ب)

- فقط `BUNDLED_PACKS` («تعطیلات رسمی» و «جشن‌های ایرانی») با `@dotlife/event-data` وارد اپ می‌شوند. بقیه‌ی بسته‌ها فقط از `@dotlife/event-data/all` در دسترس‌اند (سرور و تست‌ها) و اپ هرگز آن را import نمی‌کند.
- سرور هر بسته را با `packFileOf` فایل می‌کند؛ اپ فایل دانلودشده را با `parsePackFile` چک می‌کند (فایل خراب یا با `holiday: true` کامل رد می‌شود) و با `registerPackFile` به موتور می‌دهد. `onEventsChange` / `eventsVersion` برای نقاشی دوباره‌ی صفحه‌ها.
